# Pocket TTS 4.0.1

This release brings newer upstream generation behavior to the Rust port while preserving streaming word timestamps and highlighting in the CLI and browser.

## Generation and playback

- Port upstream text splitting and prompt-audio normalization, with a fade-in for fresh decoder output.
- Add previous-chunk continuation across the CLI, HTTP API, Python bindings and WASM, using the shared timestamp-aware streaming path.
- Reduce terminal word-highlighting flicker with buffered Ratatui updates instead of repeated full-screen redraws.
- Add audio-only checkpoint variants and pin model/voice bundles consistently.

## Word timestamps

- Refresh checkpoint attention-head selections from [pocket-tts-timestamped revision 813d892](https://github.com/dpm63/pocket-tts-timestamped/commit/813d892a64a69894750d7f42bab129ea5804a654).
- Enable timestamp heads for 14 additional configurations and update the 7M English selection. All 27 checked-in configurations now have timestamp heads.
- Use the fork's selections for 24 matching model bundles. Default English, 18M English and 2M English retain their existing weights and selections because their bundles differ from the fork.
- This is a configuration refresh, not a complete port of the timestamp fork's newer runtime changes. Accuracy varies by checkpoint; the imported selections have not undergone a new Rust audio-accuracy evaluation.

## Dependencies and packaging

- Rubato 5.0.1, SHA-2 0.11.1 and PyO3 0.29.3.
- Validate release tags against workspace, lockfile and generated WASM package versions.
- The release workflow builds a fresh browser WASM archive and SHA-256 checksum from this tag. Existing local generated packages are not reused.
- The browser archive contains JavaScript/WASM bindings, TypeScript declarations, model catalog, package metadata and third-party notices. Model weights, tokenizers, voice embeddings and the demo UI are not included.

## Validation

- 11 configuration tests passed after the timestamp-head import.
- 6 audio tests and 4 fixture-integrity tests passed with the dependency updates.
- Python bindings passed a release-profile compilation check.
- These checks do not constitute end-to-end CLI/browser listening tests or Python runtime tests. GitHub Actions reports the tagged build and packaging results separately.
